# Guide Structure — 골격 · 블록 · 문체

이 사이트의 글은 여러 분야의 법률 문제를 다루지 않는다. 항공 지연·결항 보상 한 가지 주제를 여러 각도에서
짧고 분명하게 설명하는 글이다. 그래서 메인 사이트 가이드보다 **틀을 가볍게** 쓴다 — 고정 블록을 채우는 것이
아니라, 글에 필요한 블록만 쓴다.

## 목차
1. 글 종류
2. 기본 골격
3. 페이지가 자동으로 붙이는 부분
4. 쓰지 않는 것
5. 소제목 구성 원칙
6. 블록 문법과 쓰임
7. 문체·톤 규칙
8. 분량 기준

## 1. 글 종류

| 종류 | 묶음 | 용도 | 예 |
|---|---|---|---|
| 보상·청구 글 | `claim` | 보상 기준·항공사 대응·청구와 공동소송 | EU261 지연 보상, 항공사가 기상 악화로 거절할 때 |
| 항공 상식 글 | `aviation` | 항공사 안내를 이해하는 데 필요한 업계 지식 | IATA 지연 코드, METAR·TAF 읽는 법, 항공기 정비의 종류 |
| 용어 사전 | `aviation` | 용어를 분야별로 모아 짧게 풀이, 계속 늘려 가는 긴 문서 | 항공 지연 용어 사전 |

항공 상식 글은 법률 결론을 단정하지 않는다. 마지막 소제목 하나를 **「보상과의 관계」**로 두어 그 지식이 보상 판단에서
어떤 의미인지(예: 항공사가 내세운 사유를 확인하는 단서)를 사실로 정리한다.

## 2. 기본 골격

### 보상·청구 글 / 항공 상식 글
```
:::summary        핵심 정리 3~5줄                         필수
도입              1~2문단, 첫 문장 근처에 메인 키워드        필수
## 1. …           소제목 3~5개                             필수
   └ 필요한 곳에만: :::term, 표, 사진 + :::caption, :::callout
## 자주 묻는 질문 + :::faq                                 선택 — 본문에서 못 다룬 질문이 있을 때만
```

도입 흐름: (1) 독자가 처한 상황을 2인칭으로("~하셨다면", 과장 없이) → (2) 이 글이 다루는 핵심 개념의 짧은 정의.
글이 짧으므로 도입은 길게 쓰지 않는다.

### 용어 사전
```
:::summary        이 문서를 어떻게 쓰면 되는지 2~3줄
도입              1문단
:::toc            분야가 많아 길어지므로 목차를 둔다
## 운항 시각 {#flight-times}        분야별 소제목
**STD (Scheduled Time of Departure) · 예정 출발 시각** — 풀이 2~3문장.
보상과의 관계가 있으면 한 줄 더.
…
```
- 용어마다 **굵은 표제(약어 · 한글명) — 풀이** 한 문단
- 자세한 글이 있는 용어는 풀이 끝에 링크: `[자세히](/guide/iata-delay-codes)`
- 새 용어를 더하면 `reviewedAt`을 올린다

## 3. 페이지가 자동으로 붙이는 부분 (본문에 쓰지 않는다)

- 글 머리: 「항공 보상 가이드 › 묶음」, 큰 제목(= seoTitle), 작성자·검토일, 대표 사진(cover)
- **법률 정보 안내** — 묶음별 고정 문구
- **함께 보면 좋은 글** — frontmatter `related`에 적은 글이 있을 때만 나온다. 억지로 채우지 않는다
- **맺음 상자(접수 안내)** — "내 항공편도 보상받을 수 있을까요?" + `{ctaSituation}, {ctaOffer}부터 확인해 드립니다.` + 영업일 2일·성공보수 25% 안내 + 사건 접수 버튼
- **작성·검토 표시**
- 검색엔진용 구조화 데이터 (Article, `:::faq`가 있으면 FAQPage)

`ctaSituation`·`ctaOffer` 예:
- 기상 악화 거절: `"항공사가 기상 악화를 이유로 보상을 거절했다면"` / `"그날 실제로 그런 사정이 있었는지"`
- 지연 코드: `"항공사가 알려 준 지연 사유가 납득되지 않는다면"` / `"그 사유가 보상을 막는 사정인지"`

## 4. 쓰지 않는 것

- **목차** — 짧은 글에는 과하다. 용어 사전처럼 긴 문서에만 쓴다
- **기한 상자를 습관처럼 넣는 것** — 청구 기한 자체가 글의 주제이거나 독자가 놓치면 안 되는 기한이 실제로 있을 때만
- **절차를 습관처럼 넣는 것** — 절차 흐름은 글의 주제가 절차일 때만. 특히 법인의 진행 절차(접수 → 판단 → 청구 → 공동소송)는 본문에 되풀이하지 않는다. 진행 절차와 비용 페이지(`/process`)와 맺음 상자가 맡는다
- **억지 관련 자료** — 관련 글이 없으면 `related`를 비워 둔다. 사이트 안내 페이지(보상 기준 등)는 본문 문장 속 링크로 자연스럽게 건다
- 「이런 상황이라면」 확인 섹션, 다른 주제로 보내는 분기 라인, 셀프 안내 표준 섹션
- 본문 속 접수 유도·자기 홍보 문장, 맺음 문단("지금 바로 접수하세요")

## 5. 소제목 구성 원칙

- **각 소제목(H2)이 하나의 질문에 답하도록** 쪼갠다 (예: "EU261이 적용되는 항공편", "비행거리별 금액", "보상이 줄어드는 경우")
- 절차형은 시간 순서, 쟁점형은 판단 순서, 항공 상식은 **개념 → 분류 → 확인 방법 → 보상과의 관계**
- 소제목에 번호를 매긴다 (`## 1. …`). 영문 앵커(`{#id}`)는 용어 사전처럼 목차를 쓰는 문서에만 단다
- `## 자주 묻는 질문`은 번호 없이 쓴다
- 문단은 **3~4문장** 단위로 끊는다 (모바일 가독성)

## 6. 블록 문법과 쓰임

블록은 `:::이름` 줄로 열고 `:::` 줄로 닫는다. 안에는 일반 마크다운을 쓴다. 블록 안에 블록을 넣지 않는다.

| 블록 | 언제 | 규칙 |
|---|---|---|
| `:::summary` | **항상** (본문 맨 앞) | 3~5개 목록, 결론만, 핵심 어구 굵게 |
| `:::term` | 어려운 용어가 처음 나올 때 | 1~3문장 |
| `:::caption` | 사진(`![…](…)`) 바로 다음 | 그 위치의 핵심 사실 한 문장 |
| `:::callout` | 하지 말 것·오해하기 쉬운 것이 있을 때 | 한 상자에 하나, 첫 문장 굵게. 한 글에 1~2개까지 |
| `:::flow 제목` | 글의 주제 자체가 절차일 때만 (드묾. 예: 공동소송 진행 방식, 항공사 내부 지연 처리 과정) | `1. **단계명** — 한 줄 설명` |
| `:::faq` | 본문에서 못 다룬 질문이 있을 때 | `### 질문` + 답변 2~4문장, 2~4문항 |
| `:::deadline 제목` | 놓치면 안 되는 기한이 실제로 있을 때 (드묾) | `- 항목 — 기한`, 마지막 줄은 확인 권유 |
| `:::toc` | 용어 사전처럼 긴 문서에만 | 내용 없이 열고 닫기. `## 제목 {#english-id}` 소제목으로 만들어진다 |

표: 비교·기준·금액은 서술 대신 표로. 근거가 있으면 **근거 열**(예: `EU261 제7조`), 항공 상식은 **출처 열**(예: `IATA AHM 730`).

`:::faq` 규칙: 본문 요약 반복 금지 / 사이트 `/faq`의 질문과 겹치지 않게 / "상담에서 말씀드립니다"로 끝내는 답 금지.

## 7. 문체·톤 규칙

### 7-1. 정보 우선, 광고 최소화 (최우선)
기준·금액·조건을 구체적으로. 규정 조문·기관명·코드 체계를 정확히 적어 독자가 직접 확인할 수 있게 한다.
광고성 내용은 페이지의 맺음 상자에만.

### 7-2. 근거 표기
- EU261: "EU261 제7조에 따라"처럼 조문으로. UK261도 같은 방식
- 몬트리올 협약: "몬트리올 협약 제19조(지연)"
- 국내 항공운송: "상법 제907조(여객의 연착에 대한 책임)" 등 — 조문 번호는 반드시 검증
- 국내 판례 인용 금지. 유럽사법재판소 판단은 결론만 (SKILL.md 하드 규칙 2)
- 소비자분쟁해결기준을 근거로 쓰지 않는다

### 7-3. 사이트 정책과 같은 말
비용·공동소송·연락에 관한 문장은 `topics.md` 4절의 문구를 그대로 쓴다.

### 7-4. 깊이의 상한
기준·요건은 끝까지 알려 주되, "내 항공편이 받을 수 있는가"의 결론은 단정하지 않는다 — 무엇에 따라 달라지는지(출발지, 항공사 국적, 비행거리, 도착 지연 시간, 사유)를 밝힌다.

### 7-5. 일반 문체
- 정중한 합쇼체. 조문 번역투 금지
- 영문 약어는 "STA(예정 도착 시각)"처럼 처음 한 번 풀어 쓴다
- 2인칭 상황 제시로 말을 건다
- 시각은 24시간제("18:40"), 거리는 "3,500km", 시간은 "3시간 이상"
- **굵게 표시 주의:** 굵게가 괄호·따옴표·마침표로 끝나고 바로 조사가 붙으면(`**€250~600(£220~520)**의`) 굵게가 풀리고 별표가 그대로 보인다. 괄호를 굵게 밖으로 뺀다(`**€250~600**(£220~520)의`)
- 범위는 물결 하나로 쓴다("3~4시간", "€250~600"). 취소선은 물결 두 개(`~~`)일 때만 적용된다

## 8. 분량 기준

| 구분 | 소제목 | 공백 제외 글자 수 | 이미지 |
|---|---|---|---|
| 기본 글 | 3~5개 | **2,000~3,500자** | cover + 본문 0~1장 |
| 용어 사전 | 분야 수만큼 | 제한 없음 (용어 15개 이상) | cover |

기본은 짧게. 내용이 3,500자를 크게 넘으면 한 글에 두 주제가 섞였는지 먼저 본다 — 섞였다면 두 글로 나눈다.

본문 기준(frontmatter 제외)으로 실측한다:
```bash
python3 -c "
import re,sys
t=open(sys.argv[1],encoding='utf-8').read()
t=re.sub(r'^---.*?^---','',t,count=1,flags=re.DOTALL|re.MULTILINE)
t=re.sub(r'^:::.*$','',t,flags=re.M)
t=re.sub(r'!\[.*?\]\(.*?\)|\{#[^}]*\}|\s','',t)
print(len(t))" content/blog/{slug}.md
```
