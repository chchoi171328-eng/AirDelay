# Air Guide Writer — 법무법인 명 항공 보상 가이드

AirDelay 사이트의 `/guide`(항공 보상 가이드)에 올라가는 글을 **이 저장소에 바로 반영되는 형태**
(마크다운 + 이미지)로 만든다. 메인 사이트용 `legal-guide-writer`를 바탕으로 했고, 달라진 점은
아래 표와 각 참고 문서에 적었다.

## 메인 사이트 가이드 스킬과 달라진 점

| | 메인 사이트 (`legal-guide-writer`) | 이 사이트 (이 스킬) |
|---|---|---|
| 분류 | 8개 업무분야 키 | **2개 묶음**: `claim`(보상·청구) / `aviation`(항공 상식) |
| 주소 | `/guides/{분야키}/{slug}` | `/guide/{slug}` |
| 파일 | MDX 패키지(`output/…/index.mdx`) | `content/blog/{slug}.md` + `public/images/guide/{slug}/` |
| 블록 문법 | `<GuideSummary>` 등 MDX 컴포넌트 | `:::summary` 등 블록 (이 사이트 렌더러가 처리) |
| 틀 | 요약·목차·기한 상자·FAQ·관련 자료 필수 | **핵심 정리만 필수**, 나머지는 필요할 때만 (목차는 용어 사전에만) |
| 분량 | 5,000~6,500자 | **2,000~3,500자** (한 주제를 짧고 분명하게) |
| 맺음 블록 | 본문에 직접 씀 | **페이지가 자동으로 붙임** (법률 정보 안내·접수 안내·검토 표시, 관련 글은 지정했을 때만) |
| 글 종류 | 법률 가이드 | 법률 가이드 + **항공 업계 지식**(지연 코드·기상·정비·관제) + 용어 사전 |
| 판례 | 인용 금지 | 국내 판례 인용 금지 유지. 유럽사법재판소 판단은 결론만 (아래 하드 규칙 2) |
| 근거 | 법령 조문 | 법령·규정 조문 + 항공 상식은 공식 자료(ICAO·IATA·기상청 등) |
| 이미지 | 등장인물 한국인·얼굴 비노출·텍스트 없음 | 같은 원칙 + **인물 없는 공항·항공기 장면 우선**, 영어 출발 안내판만 예외 |

변하지 않은 두 원칙:

1. **한 주제 = 한 문서.** 같은 검색어를 노리는 글을 여러 편 만들지 않는다. 보강이 필요하면 기존 글을 갱신하고 `reviewedAt`을 올린다.
2. **가이드는 사이트 안내 페이지의 한 문장을 한 편으로 펼친 것.** 보상 기준(`/services`)·진행 절차와 비용(`/process`)·자주 묻는 질문(`/faq`)이 기둥, 가이드가 가지다. 사이트에 적힌 정책과 어긋나는 문장을 쓰지 않는다.

## 워크플로우 (6단계)

### 1단계 — 중복 확인 (반드시 먼저)

글을 쓰기 전에 기존 가이드를 확인한다.

```bash
grep -H -m2 -E '^(title|seoTitle):' content/blog/*.md
```

- 같은 검색어를 노리는 글이 있으면 신규 작성을 제안하지 않고 **기존 글 갱신**을 제안한다.
- 신규를 원하면 "다른 검색 질문을 맡는 주제로 좁히자"고 제안한다
  (예: 「EU261 지연 보상」이 있으면 → 「3,500km 초과 노선의 3~4시간 지연」으로 분리).
- 판단이 애매하면 사용자에게 확인한다.

### 2단계 — 묶음·키워드·근거 확정

1. **묶음 1개**를 정한다 (`references/topics.md`). `claim` 또는 `aviation`. 둘 다 걸치면 독자가 들어오는 입구로 정한다.
2. 메인 키워드 1개 + 보조 키워드 2~3개를 정한다.
3. 규정·법령·수치·용어 정의는 **웹 검색으로 검증**한다. EU261·UK261은 조문 번호까지, 항공 용어는 공식 출처(ICAO·IATA·국토교통부·기상청 항공기상청 등)로 확인한다.
4. 글 종류를 정한다 (`references/guide-structure.md` 1절): 기본 글 / 용어 사전.

### 3단계 — 제목 2종 + 메타

- **title** — 목록·링크용 짧은 주제명 (8~18자). 후킹 금지. 예: `EU261 지연 보상`
- **seoTitle** — 글 제목(H1)·검색 결과용. `{검색어} — {독자의 질문에 답하는 구}`
  예: `EU261 지연 보상 — 유럽 출발 항공편이 3시간 늦었을 때 받는 금액`
- **summary** — 80자 이내, 메인 키워드 포함. 목록 카드와 검색 설명에 쓰인다
- **slug** — 파일 이름. 영문 소문자-하이픈 (`eu261-delay-compensation`). 한글 금지
- 주소는 `/guide/{slug}`

### 4단계 — 본문 작성

`references/guide-structure.md`를 **반드시 읽고** 골격·블록·문체 규칙을 따른다.

**골격** (본문에 쓰는 부분): 핵심 정리 → 도입(1~2문단) → 소제목 3~5개 → (자주 묻는 질문 — 본문에서 못 다룬 질문이 있을 때만)

용어 풀이·표·사진 설명·주의 블록은 **필요한 곳에만** 쓴다. 목차는 용어 사전처럼 긴 문서에만,
기한 상자는 놓치면 안 되는 기한이 실제로 있을 때만, 절차 흐름은 글의 주제 자체가 절차일 때만 쓴다.
블록을 채우려고 내용을 늘리지 않는다. 법인의 진행 절차(접수 → 판단 → 청구 → 공동소송)는 본문에 되풀이하지 않는다 —
진행 절차와 비용 페이지와 맺음 상자가 맡는다.

**본문에 쓰지 않는 것** — 페이지가 자동으로 붙인다: 법률 정보 안내, 접수 안내(맺음 상자), 작성·검토 표시,
함께 보면 좋은 글(`related`를 지정했을 때만). 맺음 상자의 첫 문장은 frontmatter `ctaSituation`·`ctaOffer`로 주제에 맞게 바꾼다.

### 5단계 — 이미지

`references/image-guide.md`를 **반드시 먼저 읽고** 진행한다.

- 수량: 대표 1장(cover) + 본문 0~2장, 16:9
- 도구: Artlist MCP, GPT Image 2.0 (`list_models`로 확인)
- **검증 게이트 필수**: 생성 이미지를 열어 확인. 얼굴·한글·로고가 보이면 재생성(최대 2회)
- 1차는 낮은 해상도로 검증, 확정 후 최종본만 높은 해상도. `confirmation_required`면 멈추고 비용 승인을 받는다
- 웹용으로 1600×900 progressive JPEG(품질 72~78, 메타데이터 제거)로 변환해 `public/images/guide/{slug}/`에 둔다
- 절차·구조는 이미지로 만들지 않는다 → `:::flow` 블록

### 6단계 — 반영과 확인

`references/md-template.md`의 형식으로 `content/blog/{slug}.md`를 만든다.

`draft` 여부는 사이트 공개 상태에 따라 정한다:
- **공개 전** (2026년 10월 현재: 자체 도메인 미연결, 모든 Vercel 배포가 로그인 보호 → 검색엔진이 접근할 수 없음):
  `draft` 없이 바로 올린다. 공개 직전에 사용자가 글 전체를 한 번 검토한다.
- **공개 후** (자체 도메인 연결 또는 보호 해제 이후): `draft: true`로 올려 미리보기에서 검토받고, 승인되면 `draft` 줄을 지운다.

공개 상태가 바뀌었는지 모르면 사용자에게 묻는다.

```bash
npm run lint && npm run build
```

빌드가 통과하면 로컬 서버에서 `/guide/{slug}`를 열어 블록이 제대로 나오는지 확인한다(데스크톱·모바일).
커밋·푸시는 사용자가 요청할 때만 한다.

사용자에게 보고할 항목: title / seoTitle / 묶음 / slug / 공백 제외 글자 수 / 이미지 검증 결과 /
유럽사법재판소 판단 언급 여부 / **사용자 확인이 필요한 사실 목록**.

## 하드 규칙 (위반 시 산출 금지)

1. **사이트 정책과 일치.** 비용·절차·연락 문구는 `references/topics.md` 4절의 확정 정책 그대로 쓴다. 정책에 없는 약속(예상 금액, 처리 기간 보장 등)을 만들지 않는다.
2. **판례.** 국내 판례 인용 금지(사건번호·"대법원은 ~ 판시" 류 모두). EU261·UK261에서 조문에 없는 기준(3시간 지연 보상, 도착 시각, 특별한 사정의 범위 등)은 "유럽사법재판소는 ~로 봅니다" 수준으로 **결론만** 쓰고 사건명·사건번호는 쓰지 않는다. 이런 문장이 있으면 보고에 표시한다. (2026년 10월 사용자 확정)
3. **소비자분쟁해결기준을 보상 근거로 쓰지 않는다.** 강제력이 없고 법원도 따르지 않는다. 꼭 언급해야 하면 "참고 기준일 뿐 강제력이 없다"는 사실로만.
4. **한국 법원 소송에서 받을 금액을 예측하거나 암시하지 않는다.** 한국 법원은 한국법으로 판단하고 재판부마다 다르며, EU 규정 금액보다 적을 수 있다.
5. **본문에 수임 유도·자기 홍보 금지.** "지금 바로 접수하세요", 승소 자랑, 공포 마케팅, 정보를 감추는 티저("자세한 내용은 상담에서") 금지. 접수 안내는 페이지의 맺음 상자 하나뿐.
6. **보장 표현 금지.** "무조건", "반드시 받습니다", "최대 600유로 받는 법" 같은 보장형 제목·문장 금지.
7. **시의성 표현 금지.** "최근", "요즘", "올해 들어". 시점이 필요하면 "2026년 10월 기준"처럼 적는다.
8. **금지어.** "무료 상담", "변협 인증", "48시간 이내"(연락은 영업일 기준 2일 이내), 공동소송 내부 최소 인원, 패소 시 비용·실비.
9. **금액 표기.** 유로·파운드는 기호+숫자(€600, £520), 원화는 "만 원" 띄어쓰기, 하한은 "부터".

## 품질 체크리스트 (전달 전 자체 점검)

- [ ] 같은 주제의 기존 가이드가 없는가 (있으면 갱신)
- [ ] 묶음이 `claim`/`aviation` 중 하나로 지정되었는가
- [ ] title은 짧은 주제명, seoTitle은 검색어 앞배치
- [ ] 핵심 정리 상자만 읽어도 답이 끝나는가
- [ ] 소제목(H2)이 3~5개이고 각각 하나의 질문에 답하는가
- [ ] 쓰지 않아도 될 블록(목차·기한 상자·절차 흐름·형식적인 FAQ)을 넣지 않았는가
- [ ] 법인의 진행 절차를 본문에 되풀이하지 않았는가 (공동소송처럼 절차 자체가 주제인 글만 예외)
- [ ] 규정·법령 근거를 조문으로 밝혔고, 웹 검색으로 검증했는가
- [ ] 항공 용어·법률 용어를 첫 등장 시 `:::term`으로 풀었는가
- [ ] 국내 판례 언급이 없는가 / 유럽사법재판소 판단은 결론만인가
- [ ] 소비자분쟁해결기준을 근거로 쓰지 않았는가
- [ ] 소송 예상 금액·보장 표현·시의성 표현·금지어가 없는가
- [ ] 비용·공동소송 일정 문구가 사이트 정책과 같은가
- [ ] 본문에 접수 유도 문장이 없는가 (맺음 상자에만)
- [ ] 독자가 놓치면 안 되는 기한이 있다면 본문이나 `:::deadline`에 적었는가
- [ ] 이미지 전부 검증 게이트 통과, 사진 아래 `:::caption`에 정보가 담겼는가
- [ ] `related`에는 실제로 함께 읽을 만한 글만 넣었는가 (없으면 비워 둠)
- [ ] `reviewedAt`이 검토한 달(YYYY-MM)인가, `draft`가 사이트 공개 상태에 맞는가 (6단계)
- [ ] 글자 수를 실측해 범위 안인가
- [ ] `npm run lint && npm run build`가 통과했는가
