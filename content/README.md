# 콘텐츠 작성 안내

보상 사례와 항공 보상 가이드 글은 이 폴더의 마크다운(`.md`) 파일로 관리합니다.
파일을 추가·수정해 저장소에 올리면 Vercel이 사이트를 다시 만들면서 목록과 상세 페이지에 반영됩니다.

- 파일 이름이 주소가 됩니다. `content/blog/eu261-guide.md` → `/guide/eu261-guide`
  (영문 소문자·숫자·하이픈만 쓰세요.)
- `draft: true`인 파일은 **미리보기 사이트에서만 보이고 운영 사이트에서는 숨겨집니다.**
  사이트를 공개하기 전(지금)에는 사이트 전체가 Vercel 로그인으로 보호되어 검색엔진에 나오지 않으므로, 새 글은 `draft` 없이 올려도 됩니다.
  게시할 때 이 줄을 지우세요.
- 이름이 `_`로 시작하는 파일은 무시됩니다(메모용).
- 필수 항목이 빠지거나 형식이 틀리면 빌드가 실패하고, 오류 메시지에 파일 이름이 나옵니다.

## 항공 보상 가이드 — `content/blog/*.md`

가이드는 날짜를 달고 흐르는 글이 아니라 **주제별로 고정해 두고 갱신하는 문서**입니다. 그래서 발행일 대신
검토일(`reviewedAt`)을 적고, 같은 주제의 글을 여러 편 만들지 않습니다.
자세한 작성 규칙은 Claude Code 스킬 `.claude/skills/air-guide-writer/`에 있습니다 ("가이드 써 줘"라고 요청하면 이 스킬을 씁니다).

```md
---
title: "EU261 지연 보상"                  # 목록·링크용 짧은 주제명
seoTitle: "EU261 지연 보상 — 유럽 출발 항공편이 3시간 늦었을 때 받는 금액"   # 글 제목(H1)·검색 결과 제목 (없으면 title)
category: claim        # claim(보상·청구) | aviation(항공 상식: 지연 코드·기상·정비·관제 등)
summary: "목록 카드와 검색 결과에 보이는 한두 문장 설명"
keywords: ["EU261", "항공 지연 보상"]     # 선택
reviewedAt: 2026-10                      # 검토한 달 (YYYY-MM)
cover: /images/guide/글주소/cover.jpg     # 선택. 없으면 묶음별 기본 이미지
related: ["다른-가이드-파일이름"]           # 선택. 적었을 때만 '함께 보면 좋은 글'이 나옵니다
ctaSituation: "유럽에서 출발한 항공편이 3시간 넘게 늦었다면"   # 선택. 맺음 안내 첫 문장을 주제에 맞게
ctaOffer: "EU261 적용 여부와 비행거리 기준 금액"             #   → "…부터 확인해 드립니다"
author: "법무법인 명"                     # 선택. 없으면 기본 작성자
---
```

본문은 마크다운에 아래 블록을 더해 씁니다. `:::이름`으로 열고 `:::`로 닫습니다.

| 블록 | 쓰임 |
| --- | --- |
| `:::summary` | 맨 앞의 핵심 정리 (결론만 3~5줄) — **항상** |
| `:::term` | 용어 풀이 (작은 회색 글) |
| `:::caption` | 바로 위 사진의 설명 |
| `:::callout` | 주의할 점 한 가지 (노란 상자) |
| `:::flow 제목` | 번호 목록을 단계 흐름으로 (절차 자체가 글의 주제일 때만) |
| `:::faq` | `### 질문` + 답변을 펼치는 목록으로 (본문에서 못 다룬 질문이 있을 때만) |
| `:::deadline 제목` | 기한 상자 (놓치면 안 되는 기한이 있을 때만) |
| `:::toc` | 목차 (용어 사전처럼 긴 문서에만). `## 제목 {#english-id}` 형식의 소제목으로 만들어집니다 |

글은 핵심 정리 → 도입 → 소제목 3~5개 정도로 짧게 씁니다. 블록은 필요한 곳에만 씁니다.
법률 정보 안내, 접수 안내, 작성·검토 표시는 페이지가 자동으로 붙이고, 「함께 보면 좋은 글」은 `related`를 적었을 때만 나옵니다.
작성 예는 `content/blog/flight-delay-3-hours.md`를 참고하세요.

## 진행 중인 공동소송 — `content/lawsuits/*.md`

진행 절차와 비용 페이지(`/process#lawsuits`)의 「진행 중인 공동소송」 목록입니다. 파일 하나가 사건 하나이고,
**단계만 공개**합니다. 원고 수·청구 금액·사건번호는 적지 않습니다. 결과는 보상 사례에 올리고 `caseSlug`로 연결합니다.
공개된 항목이 하나도 없으면 목록이 나오지 않습니다.

```md
---
airline: "○○항공"
flights: "2025년 하반기(7~12월) 운항분"   # 대상 운항 기간
stage: trial        # preparing(소장 접수 준비) | filed(소장 접수) | trial(재판 진행 중) | judgment(판결 선고) | closed(종결)
filedAt: 2026-05    # 소장 접수한 달 (YYYY-MM). preparing이면 생략
court: "서울중앙지방법원"            # 선택
note: "첫 변론기일을 마쳤습니다."     # 선택. 한 줄 안내 (금액·원고 수는 쓰지 않습니다)
caseSlug: ""        # 선택. 결과를 올린 보상 사례 파일 이름
updatedAt: 2026-10-01   # 마지막으로 고친 날 (YYYY-MM-DD) — 화면에 'YYYY.MM.DD 기준'으로 나옵니다
---
```

단계가 바뀌면 `stage`와 `updatedAt`을 고칩니다. 예시는 `content/lawsuits/example-2025-h2.md`(draft)를 참고하세요.

## 보상 사례 — `content/cases/*.md`

```md
---
airline: "대한항공"
route: "인천 → 파리"
flightDate: 2026-08-15   # 운항일
delay: "5시간 30분"      # 결항이면 "결항"
amount: 800000           # 수령 금액(원, 숫자만)
type: delay              # delay(지연) | cancel(결항)
summary: "목록 카드에 보이는 한 줄 요약"
---

본문 (선택) — 본문을 쓰면 '자세히 보기' 상세 페이지가 생깁니다.
```

사례는 의뢰인 동의를 받고 익명 처리한 실제 사건만 올려 주세요.
최근 운항일 순으로 홈 화면 '최신 보상 내역'에 최대 10건이 표시됩니다.

## 자주 묻는 질문 — `content/faq/*.md`

```md
---
question: "질문"
order: 1        # 작은 숫자가 위에 표시됩니다
category: cost  # cost(비용) | process(접수·진행) | criteria(보상 기준) | lawsuit(공동소송)
---

답변 (마크다운)
```

- 자주 묻는 질문 페이지(/faq)에는 category별로 묶여 표시되고, 홈 화면에는 위에서부터 5개만 표시됩니다.
- 법률 내용이 들어간 답변은 `draft: true`로 두었습니다. 변호사 검토 후 이 줄을 지우면 운영 사이트에 표시됩니다.
